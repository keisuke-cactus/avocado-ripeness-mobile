# 🥑 アボカド熟成度判定アプリ

アボカドの写真から、公開データセットで定義された熟成段階を5段階で推定するWebアプリです。
画像分類モデルの学習から評価、画面の実装、公開までを一通り経験するために開発しました。パソコンとスマートフォンのブラウザから利用できます。

**公開アプリ： [アボカド熟成度アプリ](https://keisuke-avocado-ripeness.streamlit.app/)**

> 学習・検証を目的とした試作アプリです。内部の傷みや食用の安全性を判断するものではありません。店頭や家庭の撮影条件での判別性能は、まだ十分に検証できていません。

## 開発の背景と経緯

アボカドは、外から見ただけでは食べ頃を判断しにくい食材です。「購入するときに写真から熟成の目安が分かれば、選ぶ手助けになるのではないか」という身近な課題をテーマにしました。

開発では、学んだ画像分類の知識を実際に使える形にすることを重視しました。

1. **公開データの確認**  
   画像と付属のExcelを照合し、熟成段階のラベル、個体の識別情報、画像の欠損を確認しました。
2. **モデルの学習と評価**  
   学習済みResNet18を利用して5段階分類のモデルを作り、未学習の個体の画像で評価しました。
3. **ローカルでのアプリ作成**  
   Streamlitで、画像の入力から推定結果の表示までを実装しました。
4. **スマートフォンから利用できる形で公開**  
   GitHubとStreamlit Community Cloudを連携し、画像のアップロードに加えてカメラ撮影にも対応しました。
5. **日常での利用を試行**  
   スマートフォンでアボカドを撮影し、選定・調理・実食まで試しました。これは利用体験の確認であり、精度や食品の安全性を裏付ける試験ではありません。

今後は、実際の撮影環境でのデータを蓄積し、利用者にとって役立つ判定に近づけることを目指しています。

## できること・使い方

1. 公開アプリを開きます。
2. 「写真を選ぶ」または「カメラで撮影」を選択します。
3. アボカドを1個ずつ、画像の中央に大きく写します。
4. 「熟成度を判定する」を押します。
5. 推定された段階と、各段階に対するモデルの出力を確認します。

アップロードはJPG・JPEG・PNGに対応しています。カメラの利用にはブラウザでのカメラ許可が必要です。

| 段階 | アプリ上の表示 |
| --- | --- |
| 1 | 未熟 |
| 2 | 熟し始め |
| 3 | 食べ頃の初期 |
| 4 | 十分に熟した状態 |
| 5 | 熟しすぎ（過熟） |

これらはデータセットの熟成指標に対応する表示名です。個々の果実について食べ頃や安全性を保証するものではありません。
棒グラフはSoftmaxによるモデルの出力分布であり、「その割合で必ず正しい」という意味ではありません。

## 使用技術と構成

| 用途 | 技術 |
| --- | --- |
| 開発言語 | Python |
| モデル学習 | PyTorch、torchvision |
| 画像分類 | ImageNetで事前学習されたResNet18を利用した転移学習 |
| 学習環境 | Google Colab、GPU（Tesla T4） |
| 画像処理 | Pillow、torchvision.transforms |
| 画面・推論処理 | Streamlit |
| コード管理 | GitHub |
| 公開環境 | Streamlit Community Cloud、CPU推論 |

```text
公開データ（画像・熟成度ラベル）
    ↓ 整合性の確認・個体単位の分割
Google Colabで学習・検証・テスト
    ↓ 学習済み重みを保存
best_model.pth
    ↓
Streamlitアプリ
    写真の選択／カメラ撮影 → 前処理 → CPUで推論 → 段階とグラフを表示
```

推論はサーバー側で行います。スマートフォン内でモデルを動かすネイティブアプリではなく、ブラウザからアクセスするWebアプリです。

## 使用データ

**['Hass' Avocado Ripening Photographic Dataset](https://data.mendeley.com/datasets/3xd9n945v8/1)** を使用しています。

- 作成者：Pedro Xavier、Pedro Rodrigues、Cristina L. M. Silva
- 公開年：2024年
- DOI：10.17632/3xd9n945v8.1
- データのライセンス：CC BY 4.0
- 対象：Hass種のアボカド478個体、画像14,710枚
- 収集目的：熟成段階の予測と棚持ち期間の推定に用いる深層学習モデルの開発

元データは保存条件を分けた果実を毎日、反対側の2面から撮影したものです。同じ個体の異なる日・向きの画像が含まれています。画像ごとに5段階の熟成指標が付与されています。

前処理では、Excelの14,722件の記録を画像と照合し、対応する画像がない12件を除外しました。

| 熟成段階 | 使用画像数 |
| --- | ---: |
| 1 | 3,568 |
| 2 | 2,228 |
| 3 | 2,756 |
| 4 | 3,294 |
| 5 | 2,864 |
| **合計** | **14,710** |

画像はリサイズ・中央切り抜き・正規化を行って学習に使用しました。元データの画像・Excelはこのリポジトリには含めていません。

## 学習・評価で工夫したこと

### 同じ個体を学習用とテスト用に混ぜない

画像を無作為に分割するだけでは、同じアボカドの別の日や別の向きの写真が、学習用とテスト用の両方に入る可能性があります。

そこで、保存グループと個体番号から個体を識別し、**個体単位で約60%・20%・20%に分割**しました。これは、類似画像の混入によって評価が過度に良くなるデータリークを防ぎ、未学習の個体に対する性能を確認するためです。

| 用途 | 個体数 | 画像数 |
| --- | ---: | ---: |
| 学習 | 286 | 8,654 |
| 検証 | 96 | 3,030 |
| テスト | 96 | 3,026 |
| **合計** | **478** | **14,710** |

### 学習済みモデルを活用する

ImageNetで学習済みのResNet18の既存部分を固定し、最後の全結合層を512入力・5出力に置き換えて学習しました。今回の学習対象は最後の分類層です。

| 設定 | 内容 |
| --- | --- |
| 損失関数 | 交差エントロピー |
| 最適化手法 | Adam |
| 学習率 | 0.001 |
| バッチサイズ | 32 |
| エポック数 | 5 |
| モデルの選択 | 検証損失が最小の重みを採用 |

前処理は、短辺256へのリサイズ、中央224×224の切り抜き、テンソル変換、ImageNetの平均・標準偏差を用いた正規化です。推論時も同じ前処理を使用します。

学習率やエポック数は今回採用した設定であり、網羅的な比較によって最適性を確認したものではありません。

## 評価結果

未学習の96個体・3,026枚のテスト画像で評価しました。

| 指標 | 結果 |
| --- | ---: |
| 5段階が完全に一致した正解率 | **65.7%**（1,988 / 3,026枚） |
| 正解から±1段階以内の予測の割合 | **97.2%**（2,940 / 3,026枚） |

「±1段階以内」は隣接する段階への誤分類も含む補助指標です。完全一致の正解率や、食べ頃・安全性の判定精度とは区別しています。

### 混同行列

行が正解、列が予測です。

| 正解 ＼ 予測 | 段階1 | 段階2 | 段階3 | 段階4 | 段階5 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 段階1 | 727 | 28 | 9 | 0 | 0 |
| 段階2 | 166 | 175 | 99 | 4 | 0 |
| 段階3 | 3 | 39 | 355 | 113 | 20 |
| 段階4 | 0 | 1 | 136 | 429 | 154 |
| 段階5 | 0 | 2 | 47 | 217 | 302 |

段階1は比較的識別しやすい一方、段階2を1、段階5を4と予測するなど、隣接段階を取り違える傾向がありました。
この結果は公開データ内での評価です。店頭で撮影した画像の正解率を表すものではありません。

## 現在の限界

- 学習画像は白背景・統一された照明などの条件で撮影されています。店頭の照明、背景、影、シール、手の写り込みなどへの対応力は未検証です。
- 対象はHass種です。他品種への適用性能は確認していません。
- 1画像・1個体を想定しており、複数個体の検出や、おすすめの個体を自動で比較・選定する機能はありません。
- アボカド以外の画像を検出して拒否する機能はありません。
- 外観画像から内部の傷みや食用の安全性を判定することはできません。
- 中央を切り抜いて処理するため、果実が端にある写真では必要な情報が失われる場合があります。

## 画像の取り扱い

入力画像は推論のためにサーバーへ送信されます。
現在のアプリコードには、入力画像をファイルやデータベースに永続保存する処理はありません。また、入力画像を使って自動的に追加学習する機能もありません。

## ローカルで起動する

Python 3.13を使用した環境を想定しています。以下はWindows PowerShellでの例です。

```powershell
git clone https://github.com/keisuke-cactus/avocado-ripeness-mobile.git
cd avocado-ripeness-mobile
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

表示されたLocal URLをブラウザで開いてください。起動中はターミナルを開いたままにし、終了するときはCtrl+Cを押します。

学習済み重みの `best_model.pth` は `app.py` と同じフォルダに置きます。推論はCPUで動作するため、ローカル実行にGPUは必要ありません。

## 公開環境

Streamlit Community Cloudで、このGitHubリポジトリの `main` ブランチと `app.py` を指定して公開しています。依存パッケージは `requirements.txt` で管理しています。

| ファイル | 役割 |
| --- | --- |
| `app.py` | 画像入力、前処理、モデル読み込み、推論、結果表示 |
| `best_model.pth` | 学習後に保存したモデルの重み |
| `requirements.txt` | 実行に必要なパッケージ |
| `README.md` | 開発背景、使い方、学習・評価方法 |
| `.gitignore` | 仮想環境などを管理対象から除外 |

このリポジトリは推論アプリの公開用です。Colabの学習ノートブックや元データは含まれていないため、ここにあるファイルだけで学習工程全体を再実行する構成ではありません。

## 今後取り組みたいこと

- 実際の店頭・家庭で撮影した画像による評価
- 撮影条件に対応するデータ拡張と、モデルの一部を追加学習するファインチューニングの比較
- 熟成段階の順序を考慮した学習・評価方法の検討
- 複数のアボカドを比較し、用途に合うものを選ぶための画面の改善
- 学習手順や評価資料を整理し、再現性を高めること
- 利用者の同意を得た画像投稿と、正解ラベルの確認・管理の仕組みづくり

将来的には、利用者と協力してデータを蓄積できる仕組みを目指しています。ただし、画像が増えるだけで精度が上がるとは限りません。モデルの予測をそのまま正解にせず、撮影条件・個体の識別・熟成状態の確認方法を整え、独立した評価データで改善を確認する方針です。

**これらは今後の計画であり、現在のアプリに実装済みの機能ではありません。**
